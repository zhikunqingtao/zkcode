# 保留执行事实的会话快照恢复

日期：2026-10-09。接续[快照恢复保护修复](snapshot-shadow-repair.md)。本次修复公开的 `POST /api/sessions/{sessionId}/snapshot/resume`，不改变普通会话打开、WebSocket 重连或文件 Undo/Rewind。

## 修复原因

原恢复先删除全部消息，再从快照重建。真正完成的任务通过 `task_results.final_message_id` 引用最终消息，因此恢复刚保存的同一快照也会违反外键。没有该引用的失败任务可能恢复成功，却丢失快照未记录的消息运行归属。删除还可能级联移除回执、后处理 journal 和工作台绑定。

恢复同时写回旧快照费用并清零 cache tokens，与已经发生且只累计一次的真实消费不一致。

## 当前恢复契约

恢复仍在同一会话、同一授权工作区中执行。快照文件格式、路由和成功响应形状保持不变。

| 情况 | 结果 |
| --- | --- |
| 当前消息序列与快照语义相同 | 通过既有准入检查后成功；保留全部消息原行 |
| 没有执行事实或运行时依赖，快照是当前历史的原样前缀 | 仅删除允许回退的普通尾部 |
| 文件快照只引用保留的消息 | 不因此阻止普通尾部回退 |
| 文件快照引用拟删除消息，或目标范围内引用不能安全判明 | 拒绝历史变化 |
| 有相关执行事实，快照与当前历史不同 | 拒绝历史变化，不推测哪些无归属消息尚未被任务读取 |
| 快照要求补回缺失 ID、改变同 ID 内容或重排现有历史 | 拒绝，不重建消息 |

历史冲突返回 `409 SNAPSHOT_HISTORY_CONFLICT`。消息所属会话错误、重复 ID、重复或非递增序号等非法输入返回 `400 SNAPSHOT_MESSAGES_INVALID`。真实数据库故障仍作为内部错误处理。失败事务不修改消息、元数据或关联事实。

比较包含消息顺序、身份、角色、正文、元数据、停止原因、用量、序号和时间。正文按完整 `Vec<StoredBlock>` 解码，禁止跳过损坏块或使用裸文本兜底；合法默认值省略、空元数据和等价时间表示按现有类型语义比较。它不是 JSON 原文相等检查。原始 JSON、原始时间文本和隐藏归属列始终保留，不插入或更新消息行。

执行保护覆盖目标 transcript 的 Run、消息归属、结果及回执、后处理、工作台、外部工具请求和工具输出引用。按实际 Run transcript 区分作用域，不把 Task 的根会话所有权直接视为对子会话历史的依赖。归属或读取范围无法确定时保守拒绝截尾。

## 保留的状态与保护

- 继续恢复模型、标题、会话状态和更新时间。权限、工作区、保留策略和运行时授权不由快照元数据重建。
- 保留当前累计 input/output/cache tokens 和费用；快照中的旧用量字段仅表示保存时的观测值，不覆盖当前消费。
- Task、Run、结果、回执、journal、资源、证据、预算和 LLM 账本不回滚，也不重放工具副作用。
- 查询执行槽、活动任务、交互、资源、合并及 pending/sealed 门控保持。HTTP 请求等待被取消时，独立写入任务继续持有执行槽，直到提交或失败。
- pending/sealed 在消息完全不变时仍可能拒绝恢复；本轮保留它以控制准入行为变化，不将它描述成保留原行时防止级联删除的必要条件。

## 兼容性边界

这是一项保守恢复修复，不是完整运行时备份还原。此前可能清空部分失败任务历史、丢弃归属或 journal 的操作会改为冲突。ackEligible 的安全同快照恢复保留 journal，后续 ACK 仍能完成；不再用成功删除 journal 作为验收条件。

当前没有持久化的消息读取边界，任务也会在执行中重新读取完整历史，故不能用最后一条有归属消息的序号或时间戳证明后缀未被消费。本次不新增数据库结构，不放宽外键，不自动创建新会话，也不补修既往已丢失的数据。
